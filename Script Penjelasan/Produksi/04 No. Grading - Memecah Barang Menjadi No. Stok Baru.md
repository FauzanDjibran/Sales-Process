# Produksi 04 — No. Grading

Mengambil barang dari Persiapan Grading dan menghasilkan **No. Stok baru**. Dipakai
di UGH, UPY, UDA, UML, UDB dan UBC.

## Kode acuan

| Bagian | File / fungsi |
| --- | --- |
| Dokumen | `production-grading.ts` → `check`, `createGrading`, `transitionGrading` |
| Pembagian nilai | `production-execution.ts` → `shareGrading`, `shareByWeight`, `shareQty` |
| Buku | `consumeBucket`, `registerDerivedStock`, `produceIntoBucket`, `linkTracking` |

---

## 1. Cara pakai

1. Workspace › Unit › tab **Persiapan Grading** › klik baris, atau **Buat Grading**.
2. Baris input: pilih atau scan **No. Job** (diambil utuh), atau **No. Stok tanpa
   Job** (boleh sebagian; isi gram).
3. Klik baris itu → **popup grading** seperti timbangan: pilih **Jenis**, ketik
   gram, Enter. Jenis tetap terpilih untuk hasil berikutnya.
4. Isi **Karyawan** (opsional, boleh beberapa) dan **Bahan Penolong** (opsional).
5. **Simpan** (Draft) atau **Posting**.

Satu dokumen boleh memuat banyak baris, asal **satu partai**. Satu baris = satu Job
utuh, atau satu No. Stok tanpa Job.

Izin: `PRODUCTION_GRADING_VIEW / _CREATE / _EDIT / _POST / _CANCEL`.

Draft → Posted; Draft → Cancelled dengan alasan. Posted final.

## 4. Perhitungan

### 4.1 Per baris dokumen (group)

```
input      = Σ nilai input baris
biaya      = Σ round(gram input × tarif terkunci)        0 bila Grading bukan proses terakhir
penolong   = bagian bahan penolong baris ini             shareByWeight(Σ penolong, gram tiap baris)
total      = input + biaya + penolong

bobot hasil = gram hasil; BJL = 0
nilai hasil = shareByWeight(total, bobot)
semua hasil BJL → nilai hasil 0, dan total menjadi scrap_amount
```

**Nilai dibagi di dalam barisnya sendiri**; baris lain tidak ikut.

**Susut** tidak punya nilai sendiri: nilai input terbagi ke gram hasil yang ada,
jadi harga per gram naik.

### 4.2 Contoh: `NG_UGH_231126_00001`

| Baris | Input | Gram | Nilai | Biaya (×10) | Total |
| --- | --- | ---: | ---: | ---: | ---: |
| 1 | LOT-A, Job `UGH_…00001` | 60 | 60.000 | 600 | **60.600** |
| 2 | LOT-B, Job `UGH_…00002` | 40 | 40.000 | 400 | **40.400** |

| Baris | Hasil | Gram | Bobot | Hitungan | Nilai |
| --- | --- | ---: | ---: | --- | ---: |
| 1 | `LOTA-1` HALUS | 38 | 38 | 60.600 × 38 ÷ 55 = 41.869,09 | **41.869** |
| 1 | `LOTA-2` HALUS-B | 17 | 17 | 60.600 × 17 ÷ 55 = 18.730,91 | **18.731** |
| 1 | `LOTA-3` BJL | 3 | **0** | BJL | **0** |
| 2 | `LOTB-1` HALUS | 39 | 39 | seluruhnya | **40.400** |

Susut: baris 1 `60 − 58` = 2 g; baris 2 `40 − 39` = 1 g. BJL 3 g bukan susut, tetapi
hasil bernilai 0.

Nilai masuk 100.000 + 1.000 = **101.000** = jumlah nilai hasil.

### 4.3 No. Stok baru

`<induk>-<n>`. Induk baris:

| Baris berisi | Induk |
| --- | --- |
| Job yang punya `prd_job.tracking_id` | No. Stok itu (asal Job) |
| Job tanpa asal | No. Stok pertama menurut abjad |
| No. Stok tanpa Job | No. Stok itu |

Hasil yang sama jenisnya dengan input **tetap** No. Stok baru.

### 4.4 Tujuan hasil

| Unit | Proses sesudah Grading | Hasil masuk |
| --- | --- | --- |
| UGH, UDA, UDB, UBC | tidak ada, ada QC | QC Check |
| UPY | tidak ada, tanpa QC | Stand By |
| UML | Job Order | Persiapan Job Order |

`job_id` hasil selalu **kosong**; `partai_id` tetap.

## 6. Jurnal

Disusun **neto per akun** (`executionJournalLines`):

```
akun WIP tiap barang:  − nilai input − nilai penolong + nilai hasil
Biaya Produksi Dibebankan:  − biaya
Beban Pemusnahan Produksi:  + scrap
```

Bila semua barang satu akun WIP, yang tersisa hanya biaya:

| `NG_UGH_231126_00001` | Debit | Kredit |
| --- | ---: | ---: |
| WIP | 1.000 | |
| Biaya Produksi Dibebankan | | 1.000 |

Bila input dan hasil berbeda akun WIP, nilai pindah antar akun itu juga. Grading di
UML tidak berjurnal dalam contoh, karena biayanya 0 dan akunnya sama.

## 8. Validasi utama

| Aturan | Pesan |
| --- | --- |
| Unit punya proses Grading | *… tidak punya proses Grading.* |
| Job masih di Persiapan Grading | *No. Job … tidak ada di Persiapan Grading unit ini.* |
| Satu Job satu Draft | *No. Job … sudah ada di Draft …* |
| No. Stok milik Job tidak diambil sendiri | *… grading mengambil Job itu utuh.* |
| Satu dokumen satu partai | *Satu dokumen hanya untuk satu partai.* |
| Ambilan tidak melebihi saldo | *Melebihi saldo (…).* |
| Posting: tiap baris punya hasil | *Isi minimal satu output.* |
| Posting: gram hasil ≤ gram input | *Output … g melebihi input … g.* |
| Hasil Barang Kelola Stok aktif | *… bukan Barang aktif dengan Kelola Stok.* |

Batas gram diperiksa per baris dokumen, BJL ikut dihitung. Form menandai *Output
melebihi* dan mengunci Posting; server menolaknya juga saat Posting (P307). Draft
tetap bisa disimpan.

## 9. Cek

| Cek | Rumus |
| --- | --- |
| Nilai | `input_value + cost_amount + aux_value` = Σ nilai hasil + `scrap_amount` |
| Biaya | `cost_amount` = Σ `prd_cost_entry.amount` dokumen itu |
| BJL | semua hasil `is_bjl` bernilai 0 |
